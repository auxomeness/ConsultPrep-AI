# Phase 6 Patient Interaction Preview

Date: 2026-10-17. Scope: Member 3 presentation and usability work at `/intake`, using synthetic information only. This evidence does not verify a real patient workflow.

## Implemented preview sequence

1. A fixed initial intake question is followed by the editable initial-concern field.
2. A local empty/whitespace check either shows a linked validation error and returns focus to the field, or displays the exact entered wording in a separately labeled **Your response · Local preview** turn. Whitespace and line breaks are preserved; the text is not summarized or labeled as saved.
3. One fixed question — “When did this concern begin, and has it changed since then?” — appears under **Synthetic preview question**. Its text states that it was not generated by AI or written by a clinician.
4. A second labeled multiline field accepts a local draft. It has no save, send, submit, or next-step action. Editing the first concern hides the conversation preview until it is checked again; the second local draft remains in component state and reappears after rechecking.

The page notice states that this is a development preview, no patient session is created, nothing is saved or submitted, no AI service is called, and no clinician receives the text. Only made-up examples were used in tests.

## Accessibility and responsive observations

- Code inspection and component tests confirm a `<main>` landmark, an `h1` followed by the conversation `h2` and turn `h3` labels, associated visible labels/instructions, and error `aria-describedby`/`aria-invalid` behavior.
- Chromium tests confirmed focus returns to the first field on a validation error. After a valid check, Tab from the local-check button reaches the second textarea without forced focus. Both textareas had a visible computed focus outline.
- Turn labels and fixture provenance are text, not color-only cues. The DOM order was verified as initial question → patient response → synthetic question; the second composer follows.
- At 375px, 768px, and 1280px, Chromium tests confirmed both response fields were visible/usable after the sequence appeared, turn order stayed intact, and document width did not exceed viewport width, including a long unbroken word. No sticky control obscures the content in this slice.
- A screen-reader usability review and full accessibility audit were not performed; no compliance claim is made.
